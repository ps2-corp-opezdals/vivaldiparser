# Git — шпаргалка

> Если не уверен(а) в понимании git посмотрите мини гайд (https://www.youtube.com/watch?v=8u6xaEYGLa0&t=13s).
>
> Здесь только команды, что они делают и когда их использовать.

---

## Перед началом работы

### `git status`

```bash
git status
```

**Что делает:** показывает, что сейчас происходит в проекте.

**Зачем:** посмотреть:

* в какой ты ветке;
* какие файлы изменены;
* есть ли незаконченные изменения.

**Можно использовать в любой момент.**

---

### `git branch`

```bash
git branch
```

**Что делает:** показывает твои ветки.

**Зачем:** посмотреть, какие ветки есть и в какой ты сейчас находишься.

Текущая ветка отмечена `*`.

Пример:

```text
* feature/login
  main
```

---

## Работа с ветками

### Создать новую ветку

```bash
git switch -c feature/login
```

**Что делает:** создаёт новую ветку и сразу переключается на неё.

**Зачем:** начать новую задачу, не трогая `main`.

Примеры:

```bash
git switch -c feature/login
git switch -c feature/profile
git switch -c feature/database
```

---

### Переключиться на другую ветку

```bash
git switch main
```

**Что делает:** переходит в указанную ветку.

**Зачем:** например, перейти из своей ветки обратно в `main`.

Примеры:

```bash
git switch main
```

```bash
git switch feature/login
```

---

### Удалить ветку

```bash
git branch -d feature/login
```

**Что делает:** удаляет ветку с компьютера.

**Зачем:** когда задача уже закончена и ветка больше не нужна.

> Удаляйте ветку только после того, как её изменения уже добавлены в `main`.

---

# Получение изменений

### `git pull`

```bash
git pull
```

**Что делает:** скачивает последние изменения из GitHub.

**Зачем:** получить свежую версию проекта.

### Обычно используем:

Перед началом новой задачи:

```bash
git switch main
git pull
```

---

# Сохранение работы

### `git add`

```bash
git add .
```

**Что делает:** говорит Git:

> "Вот эти изменения я хочу сохранить."

**Зачем:** подготовить изменения перед `commit`.

`.` означает добавить все изменённые файлы.

Можно добавить только один файл:

```bash
git add index.html
```

---

### `git commit`

```bash
git commit -m "Добавил страницу входа"
```

**Что делает:** сохраняет подготовленные изменения.

**Зачем:** создать точку сохранения.

Хороший commit:

```bash
git commit -m "Добавил форму регистрации"
```

Плохой:

```bash
git commit -m "изменения"
```

Лучше писать коротко и понятно, **что было сделано**.

---

### `git push`

```bash
git push
```

**Что делает:** отправляет твои commits на GitHub.

**Зачем:** чтобы другие участники команды увидели твою работу.

Если ветку отправляешь первый раз:

```bash
git push -u origin feature/login
```

После этого обычно достаточно:

```bash
git push
```

---

# История

### `git log`

```bash
git log
```

**Что делает:** показывает историю commits.

**Зачем:** посмотреть, какие изменения были сделаны раньше.

---

### Короткая история

```bash
git log --oneline
```

**Зачем:** быстро посмотреть историю без лишней информации.

Например:

```text
a31f42 Добавил регистрацию
b52c91 Исправил кнопку
c62da1 Добавил страницу входа
```

---

# Посмотреть изменения

### `git diff`

```bash
git diff
```

**Что делает:** показывает, что именно ты изменил.

**Зачем:** проверить свои изменения перед `commit`.

---

# Работа с `main`

## Получить свежий `main`

```bash
git switch main
git pull
```

**Зачем:** перед началом новой задачи убедиться, что у тебя самая свежая версия проекта.

---

## Создать ветку от свежего `main`

```bash
git switch main
git pull
git switch -c feature/my-task
```

**Зачем:** начать новую задачу от последней версии проекта.

---

# Обновить свою ветку

Допустим, ты работаешь:

```text
feature/login
```

А в `main` появились новые изменения.

Можно получить их в свою ветку:

```bash
git switch main
git pull
git switch feature/login
git merge main
```

**Зачем:** забрать свежие изменения из `main` в свою ветку.

> Если Git покажет конфликт — не паникуем. Сначала разбираемся, какие файлы конфликтуют.

---

# Если появился конфликт

Git может написать что-то вроде:

```text
CONFLICT
```

**Что делать:**

1. Открыть файлы, которые VS Code отметил как конфликтные.
2. Посмотреть, какие изменения предлагает Git.
3. Выбрать нужный вариант.
4. Сохранить файл.
5. Выполнить:

```bash
git add .
```

6. Затем:

```bash
git commit
```

Если не понимаете, что выбрать — **не делайте наугад**. Покажите конфликт другому участнику команды.

---

# Отмена изменений

## Отменить изменения в файле

```bash
git restore index.html
```

**Что делает:** отменяет изменения в файле, которые ещё не были сохранены через `commit`.

**Зачем:** если случайно сломали файл и хотите вернуть его к последнему сохранённому состоянию.

> Осторожно: изменения в этом файле будут потеряны.

---

## Убрать файл из `git add`

Если случайно сделали:

```bash
git add .
```

а какой-то файл добавлять не хотели:

```bash
git restore --staged index.html
```

**Что делает:** убирает файл из списка подготовленных для commit.

Сам файл при этом не удаляется.

---

# Если нужно временно убрать свою работу

### `git stash`

```bash
git stash
```

**Что делает:** временно убирает незакоммиченные изменения.

**Зачем:** например, нужно срочно переключиться на другую ветку, но свою работу пока нельзя коммитить.

Вернуть изменения:

```bash
git stash pop
```

> Если вы пока плохо понимаете Git, лучше использовать `stash` только когда действительно понимаете, зачем он нужен.

# Удаление ветки

### Локально

```bash
git branch -d feature/login
```

**Зачем:** удалить ветку со своего компьютера после завершения задачи.

### На GitHub

Обычно проще удалить ветку через GitHub после Merge.

---

# Полный сценарий одной задачи

## 1. Получить свежий проект

```bash
git switch main
git pull
```

---

## 2. Создать ветку

```bash
git switch -c feature/login
```

---

## 3. Пишем код

```text
Работаем над задачей...
```

---

## 4. Проверяем изменения

```bash
git status
```

При необходимости:

```bash
git diff
```

---

## 5. Добавляем изменения

```bash
git add .
```

---

## 6. Создаём commit

```bash
git commit -m "Добавил страницу входа"
```

---

## 7. Отправляем на GitHub

Первый раз:

```bash
git push -u origin feature/login
```

Потом:

```bash
git push
```

---

## 8. Создаём Pull Request

На GitHub:

```text
feature/login
      ↓
Pull Request
      ↓
main
```

После проверки команда добавляет изменения в `main`.

# ⭐ Самые нужные команды

Если вообще не хочется запоминать всё — запомните эти:

| Команда                      | Для чего                      |
| ---------------------------- | ----------------------------- |
| `git status`                 | Посмотреть состояние проекта  |
| `git branch`                 | Посмотреть ветки              |
| `git switch main`            | Перейти в `main`              |
| `git switch -c feature/task` | Создать ветку для задачи      |
| `git pull`                   | Скачать изменения             |
| `git add .`                  | Подготовить изменения         |
| `git commit -m "..."`        | Сохранить изменения           |
| `git push`                   | Отправить изменения на GitHub |
| `git merge main`             | Забрать `main` в свою ветку   |
| `git log --oneline`          | Посмотреть историю            |
| `git diff`                   | Посмотреть свои изменения     |

---

# 🚨 Команды, с которыми осторожно

Не используйте без понимания:

```bash
git reset --hard
```

```bash
git push --force
```

```bash
git clean -f
```

Они могут привести к потере работы.

Если кто-то говорит вам использовать такую команду — сначала убедитесь, что понимаете, что именно она изменит.

Для каждой задачи:

```text
main
 ↓

 ↓
создать свою ветку
 ↓
работать
 ↓
git add .
 ↓
git commit
 ↓
git push
 ↓
Pull Request
 ↓
проверка
 ↓
Merge
 ↓
main
```

## Главное правило команды

**Не работаем напрямую в `main`.**

Каждая задача — отдельная ветка:

```text
feature/login
feature/profile
feature/database
feature/header
feature/tests
```

После выполнения задачи:

**Push → Pull Request → проверка → Merge.**
